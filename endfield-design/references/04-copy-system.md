# 04 · 终末地文案系统（操作语汇，不是档案语汇）

**和方舟的根本差别**：方舟是"档案"——判定、归档、封存、机密；
终末地是"操作台"——同步、部署、编组、链路、就绪。前者**记录已发生的事**，后者**驱动正在发生的事**。

英语层在这里也不是装饰性的骨架，而是**状态机标签**：它要能对应一个真实状态。

## 1. 双层分工

| 层 | 角色 | 要求 |
|---|---|---|
| 英文 | 状态机标签 | 全大写、短、可对应 UI 状态（SYNCING / READY / DEPLOYED） |
| 中文 | 解释与锚点 | 4–8 字，动词或名词化动词 |
| 数字 | 事实 | 等宽，带单位（68% / 12 UNITS / 04:20） |

## 2. 英文词库

**状态**：`READY` `SYNCING` `SYNCED` `STANDBY` `OFFLINE` `LOCKED` `PENDING` `FAILED`
**动作**：`SYNC` `DEPLOY` `LINK` `SCAN` `CALIBRATE` `PURGE` `OVERRIDE` `REROUTE`
**对象**：`PROTOCOL` `SECTOR` `SIGNAL` `BANDWIDTH` `QUEUE` `UNITS` `TERMINAL` `CONDUIT` `FREIGHT`
**度量**：`PROGRESS` `RISK` `LOAD` `THROUGHPUT` `ETA` `UPTIME` `DRIFT`

写法：全大写、不加句号、不缩写到不可读（`SIG` 可以，`SG` 不行）。

## 3. 中文词库

| 类别 | 可用词 |
|---|---|
| 操作 | 同步 · 部署 · 编组 · 接入 · 校准 · 覆写 · 改道 · 清退 |
| 对象 | 协议 · 终端 · 信道 · 编组 · 站点 · 货运线 · 区块 · 干员位 |
| 状态 | 就绪 · 待命 · 离线 · 锁定 · 校验中 · 已接入 · 已同步 |
| 数字短语 | 剩余 6 小时 · 危险度 3 · 12 人编队 · 进度 68% |

**不要**用方舟那套：`档案` `卷宗` `封存` `机密` `观测记录`——那是另一个语域的词。

## 4. 编号体系

```
EF · 04 · SYNC · 01
└┬┘  └┬┘  └─┬─┘  └┬┘
 │    │     │     └ 序号
 │    │     └────── 动作/模块：SYNC / DEPLOY / LINK
 │    └──────────── 区块号
 └───────────────── 项目前缀
```

- 界面里编号要小、要等宽、要能读成"系统自己生成的"。
- 同一屏出现两套编号时，必须分工清楚（一套是区块，一套是任务）。

## 5. 字数上限

| 元素 | 上限 |
|---|---|
| 英文标题（每行） | 10 字符 |
| 中文标题 | 6 字 |
| 中文说明段落 | 60 字 |
| 状态芯片 | 4 字符（`SYNCED` 已是上限） |
| 按钮文案 | 4 字 / 2 词 |

## 6. 禁用

`极致` `赋能` `打造` `沉浸式` `未来感` `科技感` `赛博` `颠覆` `重塑` `解锁` `！` `？` `~` emoji
以及任何**没对应状态**的英文（写 `ENGAGED` 之前先问：这个状态在系统里存在吗？）

## 7. 与方舟文案的对照

| 场景 | 方舟（档案语汇） | 终末地（操作语汇） |
|---|---|---|
| 页面抬头 | `CLASSIFIED / 机密` | `SYSTEM ONLINE / 系统在线` |
| 标题 | `静默协议` | `零号协议 · 同步中` |
| 说明 | `凡与本卷冲突的记载，以本卷为准` | `链路已建立，等待编组就绪后部署` |
| 状态 | `● ACTIVE` | `● SYNCED` |
| 页脚 | `ISSUED BY / 罗德岛档案科` | `EF · 04 · SYNC · 01 / v1.0.4` |
